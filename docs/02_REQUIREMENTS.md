# 02. 要求仕様

## 1. 機能要求 (FR)

### FR-1. イベント取得
- FR-1.1: Claude Code Hooksを通じ、`PreToolUse`/`PostToolUse`/`PostToolUseFailure`/`SubagentStart`/`SubagentStop`/`Notification`/`UserPromptSubmit`/`SessionStart`/`SessionEnd`/`Stop`を取得できる。
- FR-1.2: 取得したイベントを内部フォーマット(`05_EVENT_DESIGN.md`)へ正規化できる。
- FR-1.3: Sub Agentのイベントをメインエージェントと区別し、`agent_id`単位で相関できる。

### FR-2. リアルタイム可視化
- FR-2.1: WebSocket経由でイベントを500ms以内(中央値)にフロントエンドへ配信できる。
- FR-2.2: キャラクターはイベント種別に応じ対応エリアへ移動し、作業状態を表現する。
- FR-2.3: 複数Sub Agent(3体以上)を同時に独立した状態・位置で表示できる。
- FR-2.4: エラー発生時に警告アイコンを表示する。
- FR-2.5: ユーザー入力待ち状態を表現する。
- FR-2.6: 接続断・再接続を検知しUIに反映する。

### FR-3. 情報表示
- FR-3.1: 現在の作業内容をAI社員ごとに人間可読な文で表示する。
- FR-3.2: アクティビティログを時系列表示する。
- FR-3.3: プロジェクト名・ブランチ・作業時間・セッション時間・編集ファイル数・読込ファイル数・Bash実行回数・テスト回数(成功/失敗)・Sub Agent数を表示する。
- FR-3.4: Claude Code状態(稼働中/思考中/調査中/実装中/テスト中/エラー/入力待ち/完了)をサマリ表示する。

### FR-4. プロジェクト管理
- FR-4.1: 複数プロジェクトを登録・切り替えできる。
- FR-4.2: プロジェクトごとにセッション・イベント・統計を分離管理する。

### FR-5. 履歴・統計
- FR-5.1: 過去セッションの一覧・詳細を閲覧できる。
- FR-5.2: 期間別・プロジェクト別の統計を閲覧できる。

### FR-6. 設定
- FR-6.1: Hooks接続状態を確認し、ワンクリックでセットアップできる。
- FR-6.2: 表示設定・プライバシー設定・データ保持設定を変更できる。

## 2. 非機能要求 (NFR)

| ID | 項目 | 基準 |
|---|---|---|
| NFR-1 | パフォーマンス | イベント発生からUI反映まで中央値500ms未満、100イベント/秒のバーストに耐える |
| NFR-2 | 可用性 | Claude Code側の異常(クラッシュ・Hook不達)を検知し、UIに明示する(サイレント停止を避ける) |
| NFR-3 | プライバシー | 既定でユーザープロンプト文面等の機微情報を表示・外部送信しない(オプトイン方式) |
| NFR-4 | ローカル完結性 | 既定では外部ネットワークへの送信を行わない(loopback通信のみ) |
| NFR-5 | 拡張性 | ゲーム要素・GitHub連携・DB永続化を既存アーキテクチャの破壊的変更なしに追加できる |
| NFR-6 | 保守性 | TypeScript strict、any禁止、責務分離、テスト可能な純粋関数設計を徹底する |
| NFR-7 | 可観測性 | Ingest Server自体の稼働状態・受信件数・エラー率を確認できる |
| NFR-8 | 再接続耐性 | WebSocket切断から自動復帰し、直近5分/2000件のイベントはリプレイで復元できる |

## 3. 制約・前提

- Claude Code Hooksが提供する情報範囲を超える可視化(思考内容の逐語表示、Bash終了コード等)は行わない(`04_CLAUDE_CODE_INTEGRATION.md` 3章の分類に従う)。
- MVPはDBを持たず、ローカルJSONL+インメモリで完結する。
- 単一開発者・単一マシンでの利用を第一級のユースケースとする(チーム共有は将来要件)。

## 4. スコープ外(明示的に対応しない)

- Claude Code自体の設定・権限管理UI(Claude Code本体の責務)
- Claude Code以外のAIツール(他社製コーディングエージェント)への対応
- リアルタイム音声/ボイスチャット等のコラボレーション機能

## 5. トレーサビリティ

各FRは`17_MVP_PLAN.md`のタスク、`16_TEST_PLAN.md`のテストケースと対応付けて管理する(実装フェーズでIssue/タスク管理ツールに転記する際のマッピング元とする)。
