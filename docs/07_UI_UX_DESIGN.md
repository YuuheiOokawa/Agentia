# 07. UI/UXデザイン設計

## 1. デザインコンセプト

「カイロソフト風のゲーム開発会社オフィスをドット絵で見下ろす」体験。Game Dev Story等のシミュレーションゲームの質感を直接の参照点とし、それらのコピーにはせず、以下の独自方針を持つ。

- **本物のドット絵アセット**: キャラクター・什器・床/壁は、実行時にベクター図形で描くのではなく、`tools/pixel-art`(pngjs製の手続き生成パイプライン、10.1節参照)で書き出した実ビットマップPNGを使用する。拡大時も`NEAREST`スケーリングでにじませない。
- **子供向けにしない**: ドット絵ではあるが、原色多用のポップさは避け、落ち着いた木目・アース系トーンを基調に、エリアごとのアクセントカラーで区別する。
- **情報密度と可愛さの両立**: キャラクター・什器はドット絵で表情豊かに、UIパネル(統計・ログ)は洗練されたSaaSダッシュボード風のまま対比させる。
- **「眺めていて楽しい」を演出で担保**: 移動アニメーション、待機中のうろつき(ウォンダー)、完了時のポーズ変化など、マイクロインタラクションで感情を伝える。

## 2. ビジュアルトーン

| 要素 | 方針 |
|---|---|
| カラーパレット | 床・壁はグレースケールのドット絵テクスチャをエリアのアクセントカラーでランタイム着色(tint)。什器は固定色の実ピクセルアート |
| タイポグラフィ | UIパネルはInter/Noto Sans JP等のモダンサンセリフ。オフィス内ラベルは白文字+黒縁取りでゲームのバナー風に視認性を確保 |
| キャラクターデザイン | 16×20グリッドのチビキャラ・ドット絵(idle/working/error/completedの4ポーズ)。シャツ部分のみ別レイヤーのタインタブル(白地)テクスチャにして役職色で着色し、髪・肌・目・ズボンは固定色レイヤーを重ねて色味を保つ |
| 什器 | 机+モニター・本棚・観葉植物・受付カウンター・サーバーラックをエリアごとに配置(`map.ts`の`AREA_FURNITURE`) |
| アイコン | 状態アイコンは引き続きシンプルな絵文字的ピクトグラム(📖⌨️🧪🚀⚠️💬)をキャラクター頭上に表示 |
| 効果音(将来) | MVPでは無音。Phase2以降、控えめな通知音をオプトインで追加検討 |

### 2.1 ドット絵アセットパイプライン

`tools/pixel-art/`配下に、手書きのASCIIピクセルグリッドではなく**手続き的な形状生成(円・矩形塗り)**でスプライトを構築し、`pngjs`で実PNGにラスタライズするスクリプト群を置く(`characters.mjs` / `environment.mjs` / `furniture.mjs` → `generate.mjs`で一括実行)。出力は`apps/web/public/sprites/`に配置し、PixiJSの`Texture.from()`で読み込む。キャラクターは「シャツ(タイント可能・白地)」と「髪・肌・目・ズボン(固定色)」を別ファイルに分離することで、役職ごとの色分け(`ROLE_COLOR`)を適用しても肌・髪の色が変色しない設計にしている。

## 3. レイアウト原則

- 画面は「オフィス(主役)」+「情報パネル(脇役)」の2ゾーン構成。オフィスが画面の60〜70%を占め、情報は右または下のパネルに集約し圧迫しない。
- 情報パネルは折りたたみ可能(オフィスをフルスクリーンで眺めたいユーザー向け)。
- レスポンシブは「デスクトップ優先」。ノートPC(1366px〜)を基準に設計し、タブレット幅では情報パネルをオーバーレイ化。モバイルは閲覧専用の簡易ビュー(Phase2検討)。

## 4. インタラクション原則

| 操作 | 反応 |
|---|---|
| キャラクターにホバー/クリック | 名札・役職・現在のタスク・直近ログを吹き出しでポップアップ |
| エリアにホバー | エリア名と現在の滞在人数をハイライト表示 |
| アクティビティログの項目クリック | 該当イベントを起こしたキャラクターへカメラフォーカス(将来のパン機能と連動) |
| 接続断発生 | 画面上部にトースト+オフィス全体を薄暗く演出(「Claude Codeとの接続待ち」) |
| エラー発生 | 該当キャラクター上に警告アイコン+一時的な画面フチの赤色ハイライト(1回のみ、常時ではない) |

## 5. アクセシビリティ

- 状態は色だけでなくアイコン形状でも区別する(色覚多様性への配慮)。
- 主要な状態変化はアクティビティログというテキスト情報でも必ず並行表示し、視覚表現に依存しすぎない。
- コントラスト比WCAG AA相当を情報パネルのテキストで確保。

## 6. 情報パネルの構成要素(全画面共通ヘッダ/サイド)

- 現在の作業(キャラクター別の「now doing」カード)
- アクティビティログ(タイムライン)
- プロジェクト情報(名称/ブランチ/経過時間等)
- Claude Code状態(全体サマリ: 稼働中/思考中/エラー等)

詳細な画面ごとの構成は`08_SCREEN_DESIGN.md`を参照。
