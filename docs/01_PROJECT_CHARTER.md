# 01. プロジェクト憲章 (Project Charter)

## 1. プロジェクト名

**Agentia** — Claude Codeバーチャルオフィス可視化プラットフォーム

## 2. ビジョン

「AIエージェントの働きは見えない」という課題を解く。
Claude Codeが今何をしているか(調査・実装・テスト・待機・エラー)を、まるでIT企業のオフィスでAI社員が働いているかのように**リアルタイムで楽しく可視化**する。

単なるログビューアではなく、"見ていて状況が直感的に分かり、かつ眺めていて楽しい" プロダクトを目指す。

## 3. 背景・課題

| 課題 | 現状 | Agentiaが提供する価値 |
|---|---|---|
| Claude Codeの動作がブラックボックス | ターミナルのテキストログのみ | 空間的・視覚的な状態表現 |
| 複数Sub Agentの並行動作が把握しづらい | ログが交錯して読みにくい | AI社員として空間的に分離して表示 |
| 長時間タスクの進捗が分かりにくい | スクロールして探す必要がある | 現在地・状態が一目で分かる |
| Claude Codeの利用がただの「作業」 | 淡々とした体験 | 将来的な会社成長要素でモチベーション向上 |

## 4. ゴール(何を達成するか)

1. Claude Codeの実行イベントをHooksで捕捉し、100ms〜数秒以内にブラウザへ反映する
2. 1画面で「今何をしているエージェントが何人いて、それぞれ何をしているか」が直感的に分かる
3. Read/Grep/Glob・Edit/Write・Bash・Test・Plan・Task(Sub Agent)・エラー・待機・完了の主要イベントを空間的に表現する
4. 複数Sub Agentが同時に別々のエリアで作業している様子を表示できる
5. 将来のゲーム要素(会社成長)・GitHub連携・複数プロジェクト管理へ無理なく拡張できる設計にする

## 5. スコープ

### 5.1 In Scope (MVP〜Phase 2)
- Claude Code Hooksを用いたイベント取得
- ローカルイベントサーバー(WebSocket/SSE配信)
- Next.js製フロントエンドでのバーチャルオフィス表示
- 1セッション・複数Sub Agentの可視化
- アクティビティログ、プロジェクト統計の表示

### 5.2 Out of Scope (MVPでは実装しない)
- ゲーム経験値・レベル・オフィス拡張(設計のみ先行、実装はPhase 4以降)
- GitHub連携の実イベント処理(設計のみ先行)
- マルチユーザー・マルチテナントでの共同編集
- モバイルアプリ

## 6. ステークホルダー / ペルソナ

| ペルソナ | ニーズ |
|---|---|
| Claude Codeを日常的に使う開発者(プライマリユーザー) | 作業中のエージェントの状況を離れた画面でも把握したい。放置ダッシュボードとして眺めたい |
| チームリード | メンバーがAIエージェントをどう活用しているか可視化して振り返りたい |
| プロダクト開発者自身(将来) | ゲーミフィケーションでClaude Codeの利用を習慣化したい |

## 7. 成功指標 (KPI)

| 指標 | MVP目標 |
|---|---|
| イベント発生からUI反映までの遅延 | 中央値 500ms未満 |
| 実際のツール実行とキャラクター状態のズレ | 誤表示率 5%未満(重複・逆転なし) |
| 複数Sub Agent同時可視化 | 3体以上の同時表示・状態独立管理が破綻しない |
| セッション中のWebSocket切断からの復帰 | 自動再接続かつイベント欠落なし(再送機構あり) |

## 8. 制約条件

- Claude Code Hooksが提供する情報の範囲でのみ設計する(推測や不可能な取得を前提としない。詳細は `04_CLAUDE_CODE_INTEGRATION.md` の分類表を参照)
- MVPはDBレスで良いが、将来のPostgreSQL移行を阻害しない設計とする
- ローカル環境(開発者のマシン)で完結することを基本とし、外部送信を必須にしない(プライバシー配慮)

## 9. リスク(詳細は `18_ROADMAP.md` に記載)

- Hooksから取得できる情報の粒度がUIの理想に届かない可能性 → 推測・補完ロジックで自然演出に振る
- 複数Sub Agent識別の精度 → session_id / transcript_pathベースの相関ロジックが必要
- キャラクター移動のリアルタイム性とイベント密度のバランス → 移動キュー設計で吸収

## 10. マイルストーン概要

| フェーズ | 内容 |
|---|---|
| Phase 0 | 設計(本ドキュメント群) |
| MVP | 単一エージェント可視化、5エリア、主要イベント |
| Phase 2 | 複数Sub Agent同時表示、全12エリア、プロジェクト管理 |
| Phase 3 | GitHub連携、DB永続化、統計・履歴 |
| Phase 4 | ゲーム要素(経験値・レベル・オフィス拡張) |
